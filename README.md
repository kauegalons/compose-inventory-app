# Compose Inventory App

An Android app for keeping a simple product inventory, built entirely with
Jetpack Compose and Navigation Compose. Products are registered through a form,
listed, opened individually for detail, and aggregated into stock statistics.

Built as a Mobile Development exam.

## Navigation flow

Four screens wired into a single `NavHost`, with the registration form as the
start destination.

```text
register ──(after a valid submit)──► product_list ──► product_detail/{productId}
                                          │
                                          └────────► statistics
```

| Route | Screen | Purpose |
| --- | --- | --- |
| `register` | `ProductRegisterScreen` | form to create a product, start destination |
| `product_list` | `ProductListScreen` | scrollable list of registered products |
| `product_detail/{productId}` | `ProductDetailScreen` | full attributes of one product |
| `statistics` | `StatisticsScreen` | aggregate figures across the whole inventory |

The list uses a `LazyColumn` and shows each product's name with its quantity.
Detail and statistics both return with `popBackStack()`.

## Data model

A single `Product` data class, held in memory by the `Estoque` object.

```kotlin
data class Product(
    val name: String,
    val category: String,
    val price: Double,
    val quantity: Int
)
```

`Estoque` is a Kotlin `object`, so it behaves as a process-wide singleton and
exposes the product list plus the two aggregate calculations. Because the state
lives only in memory, the inventory is empty again on every app start.

## Validation

The registration form validates before adding anything to the inventory and
reports problems through a `Toast`.

| Field | Rule |
| --- | --- |
| Nome | must not be empty |
| Categoria | must not be empty |
| Preço | must parse as a number and must not be negative |
| Quantidade | must parse as an integer and must be at least 1 |

Empty fields are reported together with a single message. Note that a price of
exactly zero passes the check, even though the message shown refers to a value
greater than zero.

Only after every rule passes does the app call `Estoque.addProduct` and navigate
to the list.

## Statistics

| Figure | Calculation |
| --- | --- |
| Total stock value | sum of `price * quantity` across all products |
| Total products | sum of `quantity` across all products |

Both are computed on demand with `sumOf`, so they always reflect the current
contents of the inventory.

## Requirements

- JDK 17, required by Android Gradle Plugin 8.x
- Android SDK with platform 34 installed
- Android Studio, or the bundled Gradle wrapper for command-line builds
- A device or emulator running Android 7.1 (API 25) or newer

## Building and running

The Gradle wrapper is committed, so no local Gradle installation is needed.

```bash
# Linux / macOS
./gradlew assembleDebug

# Windows
gradlew.bat assembleDebug
```

To install straight onto a connected device or a running emulator:

```bash
./gradlew installDebug
```

Opening the project folder in Android Studio and pressing Run works as well.

## A note on identifiers

The exam date is still baked into the project identifiers: the package and
`applicationId` are `com.example.prova_20_09_2024`, the Gradle root project is
`Prova_20-09-2024`, the theme is `Theme.Prova_20092024`, and the launcher label
in `strings.xml` is `Prova_20-09-2024`, which is the name users see on the device.

Renaming the repository does not change any of these. Updating the launcher label
is a one-line change in `app/src/main/res/values/strings.xml`; renaming the
package is a refactor across the whole module.
